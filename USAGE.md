# Как пользоваться kiborg

## Быстрый старт (5 минут)

### Шаг 1 — API-ключи

Скопируйте шаблон и вставьте свои ключи:

```bash
cp deployment/llm_keys.env.example cyborg/llm_keys.env
```

Отредактируйте `cyborg/llm_keys.env` — впишите `CLOSEROUTER_API_KEY` и/или `GEMINI_API_KEY`.

> ⚠️ **Никогда не коммитьте `llm_keys.env`** и не печатайте ключи в чат или лог. Файл уже в `.gitignore`. Без ключей kiborg работает в stub-режиме: идеи будут болванками, доставка их отбросит.

### Шаг 2 — Запустить пульт

```bash
python panel/serve.py
```

Откройте `http://127.0.0.1:8737` в браузере.

> Не запускайте два экземпляра пульта одновременно — они будут писать в один `state.json` и устроят гонку.

### Шаг 3 — Настроить источники

В пульте на вкладке настроек:

- **Telegram** — включите каналы, из которых хотите собирать новости (по умолчанию включены не все).
- **RSS / ленты** — Hacker News, Reddit, Lobsters, GitHub Trending — включите тумблеры для нужных.
- **Локальные папки** — укажите пути к проектам, если хотите идеи из кода (используется Oracle-режимом).

### Шаг 4 — Принести идеи

Нажмите кнопку **«Принеси идеи»** в пульте — или дождитесь автосбора (если включён).

Конвейер: collect → ideate → rank → readability → scrub → deliver.

Результат появится в инбоксе пульта и в `idea_engine/data/inbox.md`.

### Шаг 5 — Разобрать идеи

В инбоксе для каждой идеи:

| Действие | Что делает | Влияние на будущее |
|---|---|---|
| **Take** | Беру в работу | Система учится: такие идеи будут повторяться |
| **Later** | Интересно, но не сейчас | Не забывается, вернётся позже |
| **Trash** | Не нужно | Система учится: такие идеи не повторятся |

Повторяйте. Система становится точнее с каждым триажем.

## Oracle-режим

Oracle сканирует локальный проект, строит план улучшений по заданной цели и складывает его в инбокс.

```bash
python cyborg/oracle_mode.py --project "M:/projects/myapp" --goal "добавить авторизацию по JWT"
```

### Правила формулировки цели

**Хорошая цель** — конкретная, от 3 слов, описывает результат:
- ✅ «добавить авторизацию по JWT»
- ✅ «оптимизировать загрузку главной страницы»
- ✅ «переписать модуль отчётов на асинхронный»

**Плохая цель** — абстрактная, < 3 слов, из стоп-листа (`test`, `fix`, `run`, `plan`, `oracle`):
- ❌ `test`
- ❌ `fix`
- ❌ `улучшить`

### Ограничения

- Указывайте **корень конкретного проекта**, не корень диска. Сканирование `M:/` целиком может зависнуть на медленных/сетевых дисках.
- Символические ссылки-циклы обрабатываются, но лучше их убрать.
- Результат появляется в `idea_engine/data/oracles/` и в общем инбоксе.

## Типичные ошибки

### 🚫 Пустой инбокс после «Принеси идеи»

**Причина:** не включён ни один источник.

**Решение:** в пульте откройте настройки источников и включите хотя бы один (Telegram, RSS или папку). Проверьте, что баннер настройки не показывает ошибок.

### 🚫 Идеи — болванки, доставка отбрасывает

**Причина:** не настроены API-ключи в `llm_keys.env`.

**Решение:** проверить, что файл `cyborg/llm_keys.env` существует и содержит валидные ключи без пробелов вокруг `=` и без BOM-маркера.

### 🚫 Тесты падают на `pytest` в корне

**Причина:** коллизия имён модулей (`run.py`, `store.py` есть и в `cyborg/`, и в `idea_engine/`). Один импорт кэшируется в `sys.modules`, второй пакет получает чужой модуль.

**Решение:**
```bash
# ПРАВИЛЬНО
python run_tests.py
python run_tests.py cyborg          # только cyborg
python run_tests.py idea_engine panel

# НЕПРАВИЛЬНО — даст ложные падения
pytest
```

### 🚫 Ручное редактирование `state.json`

**Причина:** желание «почистить мусор» напрямую в файле.

**Решение:** не редактируйте `state.json` руками — это ломает инварианты хранилища (связи статусов, счётчики триажа). Используйте пульт или редактируйте `inbox.md`.

### 🚫 Ключи в чате или логе

**Причина:** копипаст ключей для отладки.

**Решение:** никогда. Ключи живут только в `cyborg/llm_keys.env`. Для проверки используйте stub-режим или логи без значений.

### 🚫 Два пульта одновременно

**Причина:** случайно запущен второй `panel/serve.py`.

**Решение:** один пульт = один процесс. Второй либо упадёт на порту, либо устроит гонку за `state.json`.

## Ключевые файлы

| Файл | Назначение |
|---|---|
| `kiborg.bat` | Windows-лаунчер: пульт, идеи, oracle, тесты, открыть папку |
| `cyborg/run.py` | CLI: один прогон «принеси идеи» |
| `cyborg/oracle_mode.py` | CLI для Oracle-режима |
| `panel/serve.py` | Веб-пульт на `127.0.0.1:8737` |
| `idea_engine/data/state.json` | Живые идеи (машина) |
| `idea_engine/data/inbox.md` | Человекочитаемый инбокс |
| `idea_engine/data/oracles/` | Планы Oracle-режима |
| `cyborg/llm_keys.env` | API-ключи (не коммитить!) |
| `cyborg/config.py` | Константы конфигурации |
| `run_tests.py` | Единственный правильный способ гонять тесты |

## Глоссарий

| Термин | Определение |
|---|---|
| **Орган** | Чистая функция `run(inputs, env) → dict`. Пример: `idea_engine/organs/ideate.py` |
| **Нерв (wiring)** | Обёртка вокруг органа: адаптирует env, добавляет cross-cutting логику. Пример: `cyborg/wiring_ideate.py` |
| **Совет** | Отбор идей тремя ролями: арбитр, интуиция, оркестратор. Файлы: `cyborg/mind.py`, `cyborg/advisors.py` |
| **Oracle** | Режим построения плана по цели для локального проекта |
| **Инбокс** | Человекочитаемый результат доставки: `idea_engine/data/inbox.md` |
| **Триаж** | Действие пользователя над идеей: take / later / trash |
| **Автосбор** | Периодический прогон конвейера, живёт внутри `panel/serve.py` |
| **Stub-режим** | Работа без ключей: идеи — болванки, доставка их отбрасывает |

---

## Примечания

- **Автосбор умирает вместе с пультом.** Это не отдельный демон, а таймер внутри `panel/serve.py`. Закрыли пульт — автосбор остановился.
- **Источники по умолчанию — только Telegram.** Для Hacker News, Reddit, Lobsters, GitHub Trending нужно включить тумблеры в пульте.
- **Триаж влияет на будущее.** Система запоминает ваши take/trash и корректирует генерацию. Чем больше разберёте — тем точнее идеи.
